# JoyAI 标注数据审计说明

本阶段只审计标注 JSON，不下载原始视频，不启动模型或 GPU。

## 运行

在仓库根目录执行：

```powershell
.\.venv-local\Scripts\python.exe datasets\audit_annotations.py `
  datasets\chat_shard_06.json `
  --output-dir datasets\audit_output `
  --sample-size 100 `
  --seed 20260730
```

输出包括：

- `summary.json`：机器可读的总体统计、异常计数、重复率和时间分布；
- `report.md`：便于人工阅读的审计摘要；
- `candidate_videos_100.csv`：可在表格软件中填写核验状态；
- `candidate_videos_100.jsonl`：供后续上游定位工具读取。

候选清单会固定纳入标注数最多和最大时间戳最长的异常项，其余名额按来源、任务类型
和最大标注时间区间分层，并使用固定种子稳定排序。
`upstream_lookup_status`、`media_download_status`、`annotation_review_status` 和
`audio_review_status` 初始状态不代表已经找到、下载或验证媒体。

## 当前审计边界

JSON 中的 `time` 是问题或回答发生的时间点，只能证明媒体至少覆盖到该时间，不能
证明视频就在该处结束。以下项目必须等取得原始媒体后再检查：

1. 实际视频时长、编码格式和可解码性；
2. 是否存在音轨、音频采样率和声道；
3. 音画是否同步，语音或环境声是否支持标注；
4. 问题与回答是否真的被相应时间点前后的画面支持；
5. 上游数据的许可、访问方式和文件名映射是否可用。

## 上游定位审计

第一阶段候选生成后，可以离线解析文件名：

```powershell
.\.venv-local\Scripts\python.exe datasets\resolve_upstream.py `
  datasets\audit_output\candidate_videos_100.jsonl `
  --output-dir datasets\audit_output
```

这一步只生成父视频 ID、片段序号、候选路径、访问要求和阻塞原因，不查询远程文件，
也不下载媒体。所有条目的 `remote_verified` 初始值均为 `false`。

缓存 Open-o3、GUI-World 和 CharadesEgo 官方标注元数据后，可以执行精确连接：

```powershell
.\.venv-local\Scripts\python.exe datasets\match_upstream_metadata.py `
  datasets\audit_output\candidate_upstream_audit_100.jsonl `
  datasets\chat_shard_06.json `
  --metadata-root datasets\audit_output\upstream_metadata `
  --output-dir datasets\audit_output
```

连接以规范化后的问题和回答为依据，并优先保留与 JoyAI 扁平名称 basename 一致的
官方路径。输出中的 `matched_unique_path` 只表示元数据路径唯一，不表示视频已经下载
或通过解码检查。`confirmed_name_collision` 表示同一个 JoyAI 文件名对应多个官方路径，
后续必须按完整路径拆分，不能继续把 `(source, video_name)` 当作媒体主键。

CharadesEgo 的 `_action_N` 应优先视为 JoyAI 预处理片段的名称。公开社区复现归档
`momo321654/Interaction-videos` 提供与 JoyAI `video_name` 对应的预切片，CharadesEgo
共两个 tar 分片，合计约 16.49 GB。JoyAI 官方材料没有说明 `_action_N` 等于官方 CSV
中 `actions` 字段的顺序，因此不能依据该序号自行裁剪父视频。

JoyAI 的 `question.time` 和 `response.time` 是交互训练中的提问/响应时刻，不是动作片段
持续时间。它们与官方 action 时长的差异不能作为标注错误证据。审计中的
`hypothetical_action_*` 字段只保留对旧假设的诊断信息，
`clip_derivation_verified=false` 表示切片生成关系并未得到证实。

详细调查见 `CharadesEgo切片调查结论.md`。

## 媒体 tar 抽样验收

取得媒体 tar 后，不需要完整解压。以下命令会扫描成员名称、与 JoyAI 标注连接、优先
使用此前 100 条候选并补足稳定随机样本，只抽取选中的 20 条：

```powershell
.\.venv-local\Scripts\python.exe datasets\audit_media_archive.py `
  D:\Downloads\CharadesEgo__001.tar `
  datasets\chat_shard_06.json `
  --output-dir datasets\media_audit_output\charadesego-001 `
  --priority-jsonl datasets\audit_output\candidate_videos_100.jsonl `
  --sample-size 20 `
  --expected-size 5738188800 `
  --decode `
  --analyze-silence `
  --extract-frames
```

程序不会调用 `tar extract`，而是把选定成员通过受控文件名复制到输出目录，避免归档
路径穿越。输出包括：

- `media_audit.jsonl/csv`：逐媒体探测结果；
- `media_audit_summary.json`：机器可读汇总；
- `media_audit_report.md`：人工摘要；
- `extracted/`：仅选中的媒体；
- `frames/`：每秒抽取的审计帧。

`ffprobe` 和 `ffmpeg` 必须在 `PATH`，也可以分别用 `--ffprobe`、`--ffmpeg` 指定完整
路径。工具缺失时条目会标记为 `tool_missing`，不会误判为通过。

`audio_usable=true` 只证明存在可探测音轨，不证明音频内容与画面或问题匹配。最终仍需
人工试听和观看。

## 转换为 Omni v1

媒体审计和抽帧完成后，可以把通过项转换成 B2 已定义的训练协议：

```powershell
.\.venv-local\Scripts\python.exe datasets\convert_audit_to_omni.py `
  datasets\chat_shard_06.json `
  datasets\media_audit_output\charadesego-001\media_audit.jsonl `
  --provenance datasets\provenance\charadesego-community-research.json `
  --output datasets\media_audit_output\charadesego-001\omni-training-v1.jsonl
```

转换器只接纳媒体、时间戳和抽帧均通过的记录，并再次调用 Omni schema 校验。原始视频
音轨被标记为 `environment_audio`；JoyAI 问题仍是 `user_text`。不能因为 MP4 有音轨，
就把合成的 JoyAI 问题误认为视频中真实说出的用户语音。
